## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Today the helper renders every profile from one embedded file, `base.sb`. With policies it renders from a policy: a fixed first part, the rules of the policy, and a fixed last part of denies that no policy may undo (later rules win, so they must be last). The helper also has to keep the policy text it was given, because root never opens a host-owned file and so cannot read it again at upgrade. This subtask changes no behaviour for users: every profile is on `default`, which must give the rules of today. The helper currently load-tests a file as root; with text from the host user that test should not run as root.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A rendered policy starts with `(version 1)` and `(deny default)` and ends with the fixed denies of the design doc, whatever the policy says
- [ ] #2 `default` renders the same rules as `base.sb` does today, pinned by a test, and the profile probes pass under it
- [ ] #3 A policy that allows `/Library` whole still cannot read `/Library/Keychains`, shown under `sandbox-exec`
- [ ] #4 The policy text is kept as given in a root-owned file beside the rendered one, and `install` renders every profile again from it
- [ ] #5 A profile from before policies, with nothing kept, renders as `default`
- [ ] #6 A kept policy that includes a name the helper does not have does not render, and `launch` refuses with the command that fixes it
- [ ] #7 The load test runs as an account without privileges and with a time limit
- [ ] #8 Interrupting the helper between any two steps leaves a profile that starts or one that the same command repairs
<!-- AC:END -->
