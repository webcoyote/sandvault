## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A policy the user wrote is a file in `~/.config/sandvault2/policies/`, and could be managed with an editor and `mv`. The commands exist for what those cannot do: show what a policy expands to, check it before it is applied, keep a broken file from replacing a working one, and refuse a removal or rename that would leave a profile or another policy pointing at nothing. The reason for each choice is under "Commands" in the design doc.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `policy list` shows the built-in policies and the ones the user wrote, and which profiles have each
- [ ] #2 `policy show NAME` prints the text; with `--expanded`, what the helper would render
- [ ] #3 `policy check NAME` parses the policy and loads it under `sandbox-exec` as the user, and reports the line of a mistake
- [ ] #4 `policy edit NAME` gives the editor a copy; a copy that fails the check never replaces the file; no profile changes, and the `profile set` command is printed for each profile that has the policy
- [ ] #5 `policy edit`, `rename` and `remove` refuse a built-in policy; `edit` names `sv2 policy new NAME --from BUILTIN`
- [ ] #6 `policy rename` and `policy remove` refuse a policy that a profile has or another policy includes, and name which
- [ ] #7 `policy remove` must be written in full, as `profile remove` must
- [ ] #8 README-SV2.md describes the commands
<!-- AC:END -->
