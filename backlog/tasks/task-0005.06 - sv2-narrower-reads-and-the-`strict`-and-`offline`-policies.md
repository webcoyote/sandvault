## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A session can read every file but those under `/Users`, `/Volumes` and `/Library/Keychains`: that was left wide by decision when the profile became default deny, and deferred to this work. `read-system` is the narrower reading and has not been measured. Two questions are open: which reads a session needs, and whether `default` moves to `read-system` or stays as wide as today with `strict` as the choice. `offline` is `default` without the network. TASK-0002 (the agent-safehouse policy) may inform `strict`.
<!-- SECTION:DESCRIPTION:END -->

- [ ] #2 `strict` and `offline` are run through the profile probes, each with its own expectations, as the current user and in a real session

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-11-27, from TASK-0002: agent-safehouse (Apache-2.0, commit 490d8d4) has a measured list of what a session reads outside its home, in profiles/10-system-runtime.sb and profiles/30-toolchains/: `/usr`, `/bin`, `/sbin`, `/opt`, `/System/Library`, `/System/Volumes/Preboot`, `/Library/Apple`, `/Library/Frameworks`, `/Library/Fonts`, named files under `/private/etc` and `/private/var`, and named devices. It is a starting list for `read-system`, to be measured with the probes here, not copied. Two techniques in it: `file-read-metadata` alone on the directories above an allowed path, so a path can be walked without the directory being listed; and paths written as the kernel sees them (`/private/etc`, not `/etc`). If rule text is copied, Apache-2.0 asks that the licence and a note of the change go with it; sandvault is Apache-2.0 as well.
<!-- SECTION:NOTES:END -->
