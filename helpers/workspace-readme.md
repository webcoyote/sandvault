# Sandvault workspace for __HOST_USER__

This directory is the shared workspace between your macOS account (__HOST_USER__)
and the sandbox account __SANDBOX_USER__. Both accounts can read and write it, so
it is how files move in and out of the sandbox.

Sandvault runs shell commands and coding agents (Claude Code, Codex, OpenCode,
Gemini, pi, Muse, herdr) as __SANDBOX_USER__, a separate limited macOS account.
That account cannot read your home directory and cannot see your other volumes,
so an agent running there sees only this workspace, its own home directory, and
the system itself.

- **Host account** — __HOST_USER__, your login
- **Sandbox account** — __SANDBOX_USER__, runs the agents
- **Sandbox home** — `__SANDBOX_HOME__`, not readable from your account
- **Shared workspace** — `__WORKSPACE__`, this directory
- **Managed state** — `_sandvault/` inside it, written by sv, leave it alone

__PROFILE_NOTE__

## Enter the sandbox

    sv shell        a shell as the sandbox account
    sv claude       Claude Code (also sv codex, sv opencode, sv gemini,
                    sv pi, sv muse, sv herdr)
    sv-clone URL    clone a repository into this workspace

## Shell configuration

__SANDBOX_USER__ sources `user/.zshrc` and `user/.zprofile` from this workspace at
login, so tool configuration belongs there, not in the sandbox home directory.
